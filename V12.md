# AI Film Studio V12 — Production Render Worker

V12 turns the render contract into a real, independently runnable FFmpeg worker.

## Architecture

Next.js creates a durable render job and manifest. It calls `RENDER_WORKER_URL` with the manifest and a callback URL. The worker:

1. downloads/reads durable media
2. renders each 5-minute manifest chunk independently
3. concatenates chunks
4. mixes voice/music/SFX with narration ducking
5. normalizes loudness
6. burns timed subtitles
7. reports progress back to the app

This keeps FFmpeg off the Next.js request path and makes 60-minute projects resumable at chunk boundaries.

## Run worker

```bash
RENDER_WORKER_SECRET=change-me node worker/render-worker.mjs
```

Then set:

```text
RENDER_WORKER_URL=http://your-worker:8787/render
RENDER_WORKER_SECRET=change-me
APP_URL=https://your-app.example
```

The worker requires FFmpeg in PATH.

## Security

Use HTTPS between the app and worker. Set `RENDER_WORKER_SECRET` on both sides. In production, put the worker behind a private network or authenticated gateway.

## Current limitation

The worker implements deterministic cuts, not advanced dissolve/transition graphs. That is intentional for the first production render worker: correctness and recoverability come before cinematic transition complexity. The timeline retains transition metadata so a later render graph can add true transitions without changing the project contract.

## Durable workflow

Set `USE_RENDER_WORKFLOW=1` and configure `RENDER_WORKER_URL`. The app starts `renderFilmWorkflow` with `start()` and returns immediately; the workflow invokes the worker as a durable step. Vercel's current Workflow SDK uses `start()` for fire-and-forget execution and `"use workflow"`/`"use step"` for durable orchestration.
